# Provider reliability and Groq provenance

OpenRouter prices of zero for prompt and completion are the monitor's criterion. An explicit `data: []` is a successful empty catalog and may legitimately remove all previous models. Missing/malformed data or malformed model/pricing entries are fetch failures, never a successful empty catalog.

Each successful provider replaces only its portion of `snapshot.json`. Failed and unselected providers retain their previous entries. Old raw OpenRouter IDs are normalized, so existing snapshots need no migration. No cached entries means `unavailable`, rather than inventing data. A successful empty snapshot is still an existing baseline: a later model is reported as added. `--init` resets successful provider baselines only, preserving failed/unselected provider entries.

Incomplete checks return **1**, including a healthy provider returning empty while another fails. JSON still reports observed changes from healthy providers, `complete: false`, `errors`, and `provider_status` (`fresh`, `static_unverified`, `cached`, `unavailable`). `provider_counts` counts successful catalogs only, including successful zero. Complete checks return 0 for initialization/no changes and 2 for changes. Unknown/empty provider selection is rejected by argparse (exit 2).

The merged snapshot retains last known data; it does not assert cached availability. Cached providers are excluded from fallback selection. Unselected providers are preserved without announcing removal. On recovery, genuine removals are reported once. All-provider failure does not rewrite snapshot/history. During partial failure, healthy observations can update snapshot/history but no notification is sent, even with `--notify-always`. Consequently, a healthy-provider change observed during a partial failure is recorded locally and is not re-alerted on recovery; inspect the incomplete JSON report/history.

Groq's [models documentation](https://console.groq.com/docs/models) describes authenticated `GET https://api.groq.com/openai/v1/models`, returning active models. It requires `GROQ_API_KEY` and does not certify free eligibility. [Rate limits](https://console.groq.com/docs/rate-limits) distinguish plan/account limits; active availability is not a guarantee of zero price or quota for a particular account.

The legacy manual Groq list is retained for compatibility, with `source: legacy_manual_candidates`, `catalog_as_of: null` (original date unknown), `reviewed_at: 2026-09-30` (provenance review, **not** a freshness claim), and `free_tier_verified: false`. It may contain retired models. JSON exposes the source under `catalog_metadata`; text labels Groq additions/removals as manual catalog changes. Candidates are excluded from automatic fallback suggestions even if listed in the fallback chain. The compatibility name `fetch_groq_free` is retained; it is not evidence of free eligibility.

No authenticated Groq path was added: the implementation environment had no configured key, and active-model enumeration alone cannot answer the monitor's free-tier question. No key was requested, created, exposed or changed. To monitor only verified zero pricing, select `--providers openrouter`. This code makes no claim about current live account quotas. Tests use simulated responses and temporary state, with no live monitor notifications.

Validation: `python3 -m unittest discover -s tests -v` and `ruff check .`. Regression coverage includes partial/all failures, successful empty responses, invalid payloads, disabled providers, missing and empty cache, recovery, no-op, legitimate removals and exclusion of stale/unverified fallbacks.
